- Split vitest into `unit` and `integration` projects: the suite is now 36 files and ~110s, and `src/**/*.test.ts` pays for a DB reset it never uses.
- A test asserting `reset-db.ts` covers every model in the Prisma client, so adding a model fails loudly instead of leaking rows between tests (and stops the "all 19 models" line in docs/testing.md going stale).
- `@helpers/trpc` now exports `createCallerFromToken` (real `createContext`) and `expectTrpcError`; use them in Phases 5.b–5.d instead of hand-rolling `rejects.toMatchObject`.
- A shared `@helpers/wait-for` poller now exists for endpoints that write after responding; reuse it in Phase 4/6 rather than sprinkling `setTimeout`s.
- A lint/CI check that every command shown in a docs code block actually runs; three snippets in docs/testing.md were wrong on first draft and only caught by hand-checking against the source.
- A `createTwoOrgs()` helper: every router test rebuilds the same "caller's org + a stranger's org" cross-isolation fixture by hand.
- An `expectAuthProcedures(router, calls)` helper: the last block of every TRPC test file is the same hand-written `it.each` asserting UNAUTHORIZED with no user.
- A `helpers/factories` fixture that seeds a whole org graph (org + list + subscribers + campaign + messages) in one call, so the dashboard/stats tests in Phase 5.d don't each rebuild it.
- A script that boots a throwaway Postgres via Docker for tests, so the suite does not depend on a pre-provisioned local database.
- A `webhook-log` factory now exists and `createMessage` takes `tries`/`lastTriedAt`/`error`; reuse them rather than raw `prisma.*.create` in Phase 7.
